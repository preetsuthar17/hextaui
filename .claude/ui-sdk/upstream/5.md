## Summary

The `definePrimitive` sketch in `contributing/architecture.md` returns `role: "option"` from the item's `attrs`. The rest of core says the opposite:

- `RoleFields.role` in `packages/core/src/foundation/kernel/primitive-types.ts`: "Never put `role` in `attrs`."
- `packages/core/skills/ui-sdk/references/create-component.md`: "Each part's role goes on its slot (`role: "option"`), never in `attrs`."
- `checkRole` in `packages/core/src/foundation/kernel/dev.ts` warns when a slot declares a role and its `attrs` writes one too.

## Fix

A one-file change is ready on a fork. I couldn't open a pull request, since the repo only takes them from collaborators:

https://github.com/preetsuthar17/ui-1/compare/main...docs/architecture-slot-role (commit a892e03, `docs: declare the item's role on its slot in the architecture sketch`)

It declares the role on the slot, with the `focus` and `press` the role needs, and leaves only ARIA in `attrs`. It uses `menuitem` instead of `option`: the sketch has no selection, and an `option` slot doesn't compile without `aria-selected` in its `attrs`. The item is shown while open, highlighted and pressed, so it's the menu pattern anyway. Compiled against `tsconfig.test.json`: `menuitem` compiles, and `option` fails on the missing `aria-selected`. `pnpm format` and `pnpm lint` pass.

## Also

The core docs pages still put `role` in `attrs`: `core/compose-behaviors`, `core/behaviors/focus`, `core/behaviors/selection`, `web-components/installation` and `agents/connect-an-agent/your-components`. That works, since only declaring both warns, but it contradicts the skill. Moving them is a bigger rewrite: a declared `radiogroup` needs `keys` before the tutorial adds the keyboard. Worth deciding whether those pages should move to slot roles too.
