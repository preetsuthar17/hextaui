## Summary

With `data-agent-confirm` on a button, `createAgent({ allow })` asking the person, and `registerTools(agent, { allow })` refusing `press`, a WebMCP press asks the person first. They say yes, the `registerTools` check then refuses, and the step fails with `The person said no to "…"`. The person said yes; the app's own policy refused.

## Where (commit c53df2f)

`packages/core/src/page/agent/agent.ts`

- `allowed()` (around line 1161) runs `options.allow` and then `callerAllow`, in that order, and returns a plain boolean.
- `ask()` in `perform()` (around line 1241) turns any refusal of a step with a confirm into `The person said no to "${confirm}".`

## Repro

Run in vitest with jsdom against `main`:

```ts
const tools = new Map()
Object.assign(document, { modelContext: { registerTool: async (tool) => void tools.set(tool.name, tool) } })
const person = vi.fn(() => true)
const agent = createAgent({ allow: (step) => (step.confirm ? person() : true) })
registerTools(agent, { allow: (step) => step.action !== "press" })

const instance = button({ id: "save" })
const el = document.createElement("button")
el.textContent = "Save"
el.setAttribute("data-agent-confirm", "Saves for everyone")
document.body.append(el)
bind(instance.part("root"), el)

await tools.get("act").execute({ steps: [{ ref: "Save", action: "press" }] })
// { ok: false, error: { step: 0, message: 'The person said no to "Saves for everyone".' } }
person.mock.calls.length // 1
```

## Expected

- The person isn't asked about a step the app will refuse anyway.
- A refusal by the app's policy doesn't say the person said no.

## Why an issue and not a pull request

The `registerTools` JSDoc says its `allow` runs "after the agent's own `allow`", and either check can be a person (the JSDoc example calls `confirm()`). Changing the order, or how a refusal is attributed, changes that contract. A couple of options:

- `allowed()` reports which check refused, and `ask()` says `The person said no` only for a check the app marks as a person's, and `The app refused press on c1.` otherwise.
- The order flips so `registerTools`' check, the browser-agent policy, runs first, with the JSDoc updated to match.

Happy to open a pull request for whichever you prefer.
