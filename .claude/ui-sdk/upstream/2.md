## Summary

When an app cancels an agent's change in its change callback (`details.source === "agent"`, then `details.cancel()`), `agent.act()` returns `ok: true`. The only sign is `result: false` on the step, so an agent that checks `ok` reports a change that never happened.

## Where (commit c53df2f)

`packages/core/src/page/agent/agent.ts`, `act()`: a step whose api call returns `false` after a cancel is recorded with `result: false` and no `changes`, and the call still ends with `ok: true`. The test "the app can refuse a step in its change callback, since it knows the agent asked" in `packages/core/test/agent.test.ts` checks only that `changes` is undefined.

## Repro

Run in vitest with jsdom against `main`:

```ts
const agent = createAgent()
const instance = checkbox({
  id: "terms",
  onCheckedChange: (_checked, details) => {
    if (details.source === "agent") {
      details.cancel()
    }
  },
})
const label = document.createElement("label")
const el = document.createElement("button")
label.append(el, "Accept")
document.body.append(label)
bind(instance.part("root"), el)

await agent.act({ steps: [{ ref: "Accept", action: "setChecked", args: [true] }] })
// { ok: true, steps: [{ step: 0, ref: "c1", result: false }], values: { "c1 Accept": false } }
instance.get().checked // false
```

## Expected

Probably `ok: false` with an error, like `allow` refusing the same step: `{ step: 0, message: "The app refused setChecked on c1." }`. Later steps would stop too, since they may depend on this one.

## Why an issue and not a pull request

It changes what `act` returns, and some apps may rely on cancelling as a soft refusal that lets the remaining steps run. A cancel also can't be told apart from an api call that returns `false` for another reason, so the fix may need the change details (`canceled`) and not the return value. Happy to open a pull request once the intended result is clear.
